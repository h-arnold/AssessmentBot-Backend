# Release v0.7.1

Patch release fixing prompt-template resolution in the production container image.

## Release highlights

- Fixes a production failure where every assessment failed with `Markdown file not found in candidate paths` because the build copied the prompt templates to `dist/src/src/prompt/templates` instead of `dist/src/prompt/templates`.
- Adds an E2E regression test that reproduces the production image layout and asserts every prompt template resolves.

## Details

### Fixes

- The Nest build asset for `prompt/templates` no longer declares its own `outDir`. With `rootDir: "./"` in `tsconfig.json`, the Nest CLI strips that root before copying, so the configured destination landed one directory level too deep. Templates now build to `dist/src/prompt/templates`, which is where `readMarkdown()` looks.
- Removed the third, unreachable template candidate in `readMarkdownFromCandidates`. It resolved `../prompt/templates` against `process.cwd()`, producing `/prompt/templates` in the container, despite a comment claiming it was relative to the module.
- `getCurrentDirname()` is unchanged and remains exported; it no longer has an internal caller.

### Build

- `nest-cli.json` sets `deleteOutDir: true`. This Nest CLI version never cleans the output directory by default, so stale build artefacts could otherwise survive a build and mask a reintroduced fault.
- No runtime dependency, API, or environment-variable changes.

### Tests and documentation

- Added `test/prompt-template-resolution.e2e-spec.ts`, covering the compiled asset layout and template resolution from an application root containing only `dist`, mirroring the production image.
- Corrected documentation describing template resolution, the `readMarkdown()` error cases, `getCurrentDirname()`, and the linter-override line references. The template security notes no longer claim symlink protection the path guard does not provide.

## Verification

- The production build passes, with templates at `dist/src/prompt/templates` and no `dist/src/src` directory.
- ESLint, the British-English compliance check, and the formatter pass.
- The unit suite passes with 752 tests across 57 test files.
- The mocked E2E suite passes with 64 tests and one existing todo.

## Upgrade notes

- The HTTP API and environment-variable contract are unchanged.
- Redeployment is required: the fix only takes effect in a newly built container image.
